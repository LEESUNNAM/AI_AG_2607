# 티스토리 블로그 작성기

주제 하나를 처음부터 끝까지 조사된 티스토리 글로 만듭니다: 조사 → 초안 작성 → 로그인 인계 → 티스토리 에디터에 입력 → 임시저장 → 사용자의 명시적 승인(및 공개/비공개 선택) 획득 → 발행. 순서가 중요합니다 — 사용자가 초안을 보고 승인하기 전까지는 아무것도 실제로 공개되지 않습니다.

## 왜 이런 형태인가

실제 공개 블로그에 발행하는 것은 되돌리기 어려운 행동입니다 — 일단 공개되면 누구나 읽을 수 있고, 실수를 알아차리기도 전에 색인되거나 공유될 수 있습니다. 그래서 이 스킬은 조사 후 바로 발행하는 대신, 항상 임시저장 단계에서 멈춰 사용자에게 확인을 받습니다. 또한 Claude가 사용자의 카카오/티스토리 비밀번호를 절대 건드리지 않는다는 뜻이기도 합니다: 로그인은 우회해야 할 빈틈이 아니라 의도적인 인계 지점입니다. 이 두 가지는 단순한 예의가 아니라 반드시 지켜야 할 원칙으로 취급하세요.

## 1. 브라우저 도구 로드하기

`mcp__claude-in-chrome__*` 도구가 아직 로드되지 않았다면, 다른 작업을 하기 전에 `ToolSearch` 호출 한 번으로 핵심 도구 세트를 로드하세요(정확한 쿼리는 claude-in-chrome 스킬/지침 참고). 그런 다음 `tabs_context_mcp{createIfEmpty: true}`를 호출해 작업할 탭을 확보하세요.

## 2. 주제 조사하기

조사에는 기본적으로 `WebSearch`/`WebFetch`를 사용하세요 — 더 빠르고 검색 결과 페이지에 스크린샷을 낭비하지 않습니다. 검색 스니펫만 보고 쓰지 말고, 유망한 결과에서 실제 내용을 가져오세요(이 프로젝트의 research-report 스킬과 동일한 기준). 사용자가 명시적으로 요청하거나 WebSearch를 사용할 수 없는 경우에만 Chrome 브라우저를 통한 조사(구글 검색 + 기사에 `get_page_text` 사용)로 대체하세요.

- 주제별 정리 글 하나에는 서로 독립된 실제 출처 3~5개를 목표로 하세요 — 섹션마다 할 말이 있을 정도면서, 링크 모음집이 되지 않을 정도로.
- 시간에 민감한 내용은 게시일을 기록해두고, 출처마다 내용이 다르면 하나를 조용히 골라잡지 말고 그 사실을 언급하세요.
- 주제가 한 번에 조사하기엔 너무 넓다면(예: 그냥 "AI"), 작성 문서 스킬과 마찬가지로 사용자에게 범위를 좁혀달라고 요청하세요 — 범위가 없는 주제로 만든 블로그 글은 결국 내용이 얕아집니다.

## 3. 글 초안 작성하기

블로그 글은 정식 보고서와는 다르게 읽힙니다 — 분석가가 아니라 피드를 훑어보는 독자를 위해 쓰세요:

- **제목**: 구체적이고 명확하게(주제, 그리고 시간에 민감한 정리 글이라면 날짜 범위까지 포함) — 막연한 라벨이 아니어야 합니다.
- **도입부**: 독자가 무엇을 얻게 될지, 왜 읽을 가치가 있는지 알려주는 짧고 대화체인 훅(1~2문장) — "이 보고서는 ~을 다룹니다" 같은 건조한 문장이 아니어야 합니다.
- **본문**: 주요 발견/주제마다 한 섹션씩, 각각 짧은 소제목을 붙입니다(예: "1. ...", "2. ..."). 격식 있는 보고서 문체보다 편안한 1인칭 어조로 쓰세요(한국어의 경우 -습니다/-해요 톤). 문단은 짧게 유지하세요 — 블로그 독자에게는 문단당 3~5문장이면 충분합니다.
- **마무리**: 섹션들을 하나로 묶어주는 짧은 마무리와, 관련이 있다면 앞으로 지켜볼 점을 언급하세요 — 위 섹션 목록을 그대로 반복하지 마세요.

사용자가 쓰는 언어에 맞추세요(이 프로젝트는 기본적으로 한국어). 출처나 통계를 지어내지 마세요 — 조사한 내용이 어떤 부분에서 부족했다면 억지로 채우지 말고 그대로 밝히세요.

## 4. 티스토리 진입 — 로그인은 사용자에게 인계

`tistory.com`으로 이동하세요. 이미 로그인되어 있는지 확인하세요(헤더에 "글쓰기" 버튼과 프로필 아이콘이 보이면 로그인된 상태 — 곧바로 5단계로 진행). 로그인되어 있지 않다면:

1. 로그인 플로우로 이동하세요(예: "카카오계정으로 시작하기").
2. **여기서 멈추고 사용자에게 로그인 페이지가 열렸다고 알리세요.** 계정 비밀번호를 입력하는 것은 Claude가 절대 해서는 안 되는 일입니다(사용자가 자격 증명을 공유하겠다고 제안해도 마찬가지입니다) — 사용자가 직접 카카오 로그인 폼에 아이디/비밀번호를 입력해야 합니다.
3. 사용자가 완료했다고 말할 때까지 기다린 다음, 다음 단계로 넘어가기 전에 스크린샷으로 로그인 성공 여부를 확인하세요(위와 동일한 헤더 단서 사용). 애매하면 추측하지 말고 물어보세요.

## 5. 글 작성 에디터 열기

로그인된 티스토리 홈페이지에서 "글쓰기"/"쓰기" 링크를 (`find`를 통해) 찾으세요 — 블로그 서브도메인을 추측하거나 하드코딩하지 마세요. 이렇게 하면 실제로 로그인된 사용자의 블로그(`https://<서브도메인>.tistory.com/manage/newpost`)로 정확히 연결됩니다. 링크를 클릭하거나, URL을 확보했다면 바로 이동하세요. 확인된 블로그 서브도메인은 기억해두세요 — 같은 세션에서 사용자가 나중에 글을 수정하거나 공개 상태를 바꿔달라고 하면 7단계에서 다시 필요합니다.

## 6. 글 입력하고 임시저장하기 — 절대 건너뛰지 말 것

제목 필드를 클릭해 제목을 입력하고, 본문으로 탭/클릭 이동해 전체 글을 입력하세요(단락 사이에 `\n\n`을 넣은 단일 `type` 동작이면 티스토리 에디터에서 잘 작동합니다). 사용자가 사용할 카테고리를 알려주지 않았다면 카테고리는 "카테고리 없음" 그대로 두세요.

**임시저장**을 클릭하세요. 사용자의 원래 요청이 "발행해줘"였더라도 완료/발행은 아직 클릭하지 마세요 — 사용자가 아직 실제 글 내용을 보지 못했으므로, 요청 문구와 상관없이 임시저장 후 승인받는 절차는 항상 적용됩니다.

## 7. 승인 요청 후 발행하기

초안이 저장되었다고 사용자에게 알리고, 발행 전에 확인을 요청하세요. 사용자가 아직 공개(public) 또는 비공개(private)를 말하지 않았다면 물어보세요 — 실제로 결과가 따르는 선택이므로(공개 글은 누구나 볼 수 있음) 임의로 기본값을 정하지 마세요. 승낙과 공개 여부 둘 다 확인했다면:

1. **완료**를 클릭해 발행 대화상자를 엽니다.
2. 해당하는 라디오 버튼(공개 / 공개(보호) / 비공개)을 선택하세요 — 제출 버튼의 라벨이 선택에 맞춰 바뀝니다("공개 발행" / "비공개 저장" 등), 클릭하기 전 올바른 항목을 선택했는지 확인하는 좋은 단서입니다.
3. 제출 버튼을 클릭하세요.
4. 결과를 보고하고, 공개로 발행되었다면 실제 게시 URL도 함께 전달하세요.

**이미 발행된 글의 공개 상태 변경하기**(흔한 후속 요청): `https://<블로그-서브도메인>.tistory.com/manage/post/<id>`로 이동해(숫자 ID는 글의 URL이나 글 관리 목록에서 확인 가능) **완료**를 클릭해 동일한 발행 대화상자를 열고, 라디오 버튼을 전환한 뒤 저장하세요. 최초 발행과 동일한 대화상자, 동일한 흐름입니다 — 내용을 다시 작성할 필요는 없습니다.

## 예외 상황

- **사용자가 조사를 요청하는 대신 직접 자료를 제공하는 경우**: 웹 조사를 건너뛰고, 사용자가 준 자료로 글을 구성하며, 내용을 부풀리기 위해 추가 주장을 지어내지 마세요.
- **사용자가 "그냥 바로 발행해"라고 명시적으로 말하는 경우**(승인 단계를 건너뛰라는 뜻): 그래도 먼저 임시저장을 하고, 발행 전에 제목과 섹션의 짧은 요약을 보여주세요 — 이 관문의 목적은 절차상의 번거로움이 아니라 실수가 있는 글이 공개되면 되돌리기 어렵다는 데 있으므로, 임시저장 단계를 건너뛰더라도 확인 자체는 생략하지 마세요.
- **한 계정에 티스토리 블로그가 여러 개인 경우**: "내 블로그"가 두 개 이상 나타나면 에디터를 열기 전에 추측하지 말고 어느 블로그인지 물어보세요.
- **작업 중 로그인 세션이 만료되는 경우**: 이동했는데 예상치 못하게 다시 로그인 페이지로 떨어진다면, 무작정 재시도하지 말고 멈춰서 다시 사용자에게 인계하세요.
