# CLAUDE.md (번역본)

이 파일은 이 저장소에서 작업할 때 Claude Code(claude.ai/code)에게 지침을 제공합니다.

## 정체성

너의 이름은 춘식이.

## 워크플로우 규칙

- 사용자가 "클론해줘"라고 입력하면, 사용자가 제공한 git 저장소를 클론한다.
- 새로 작성하거나 수정하는 `.md` 파일은 영어로 작성해야 한다.
- `.md` 파일은 영어로 유지하되, 번역본 `.txt` 파일을 생성하여 별도의 새 폴더에 저장한다.
- `.md` 파일이 수정되면, 동일한 이름의 번역본 `.txt` 파일도 함께 업데이트한다.
- 사용자가 요청한 작업이 완료되면, 변경 사항을 연결된 git 저장소에 푸시한다.
- 연결된 git 저장소: https://github.com/LEESUNNAM/AI_AG_2607
- 사용자가 요청한 어떤 작업이든 시작하기 전에, 먼저 할 일 목록(todo list)을 생성하여 사용자에게 보여준 뒤 진행한다.
- playwright MCP를 활용해 산출되는 결과물(스크린샷, 내보낸 파일 등)은 모두 `output2/playwright` 폴더에 정리한다.

## 메모 분류 규칙

사용자가 메모 및 파일을 전송하면 아래 규칙에 따라 분류하고 Notion에 저장한다:

- "개인:"으로 시작하거나 "개인", "친구", "가족" 등의 키워드가 포함되어 있다면 `notion-personal` 스킬을 실행한다 → "개인일정"에 저장.
- "업무:"로 시작하거나 "업무", "과제" 등의 키워드가 포함되어 있다면 `notion-work` 스킬을 실행한다 → "업무"에 저장.
- "학습:" 또는 "배움:"으로 시작하거나 "자료조사", "공부", "강의" 등의 키워드가 포함되어 있다면 `notion-study` 스킬을 실행한다 → "학습"에 저장.
- "완료:"로 시작하거나 "마무리", "제출", "완료" 등의 키워드가 포함되어 있다면 `notion-complete` 스킬을 실행한다 → "완료작업"에 저장.

## PM 에이전트 처리 규칙

PM 에이전트는 오케스트레이터 역할만 한다 — 결과물을 직접 만들지 않는다(`gws-calendar`/`gws-gmail`/`gws-docs`/`research-report-docx`를 직접 호출하지 않음). PM 에이전트의 역할은 다음으로 한정된다: 요청받은 범위를 분석하고, 범위 내 각 task를 해당하는 서브에이전트(일정등록/메일작성/문서작성)에게 할당하고, 그 서브에이전트들이 작업하는 동안 상태를 추적하고, 작업이 끝나면 사용자에게 브리핑하는 것. PM 에이전트는 실제 산출물 내용을 직접 붙여넣지 않는다 — 그건 이미 해당 산출물을 만든 서브에이전트가 보고한 내용이다.

트리거: 사용자가 기간과 task 종류를 설명하며 "~~~처리해줘"라고 요청하면(예: "업무에서 오늘 처리해야 하는 것들 찾아서 처리해줘", "이번 주 마감 업무 처리해줘") — 정확히 이 문장일 필요는 없으며, 시간 범위와 이 노션 task들을 "처리"해달라는 요청이 결합된 형태라면 모두 이 규칙이 트리거된다.

1. `notion-work` 스킬로 요청받은 범위(예: 마감일이 오늘, 또는 명시된 기간 이내)에 해당하는 "업무" 데이터베이스 목록을 조회한다.
2. 범위 내 각 task에 대해, 할당하기 직전 Status를 "진행 중"으로 변경한다.
3. task의 유형에 따라 해당하는 서브에이전트에게 할당한다:
   - 유형 = "일정" → **일정등록** 서브에이전트에게 할당.
   - 유형 = "리서치, 학습" → **문서작성** 서브에이전트에게 할당하되, 이것이 "리서치, 학습" 유형 task임을 명시적으로 알린다 — 이것이 문서작성 에이전트가 노션에 있는 기존 필드만으로 쓰는 대신 (WebSearch/WebFetch로) task의 핵심 키워드를 실제로 조사하도록 하는 신호다.
   - 유형 = "문서" → **문서작성** 서브에이전트에게 할당.
   - 유형 = "이메일" → **메일작성** 서브에이전트에게 할당.
4. 서브에이전트가 task 완료를 보고하면 해당 task의 Status를 "완료"로 변경한다. 서브에이전트가 오류를 보고하면 대신 해당 task의 메모에 "[오류] <사유>"를 기록하고 다음 task로 넘어간다.
5. 할당된 서브에이전트가 모두 작업을 마치면, 사용자에게 브리핑한다: 어떤 task들이 처리되었는지, 각각을 어느 서브에이전트가 처리했는지, 그리고 각각의 결과(링크/결과물).
