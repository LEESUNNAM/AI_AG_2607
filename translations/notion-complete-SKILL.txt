# 노션 완료작업 아카이브

사용자가 끝낸 항목을 노션의 "완료작업" 데이터베이스에 기록하고, 이를 원래 항목이 있던 개인일정(개인 일정), 업무, 학습 데이터베이스와 연결합니다. Notion API 도구(`notion-fetch`, `notion-create-pages`, `notion-update-page`, `notion-search`, `notion-query-data-sources`, `notion-get-users`)만 사용하며, 브라우저 자동화나 Playwright는 절대 사용하지 않습니다.

## 이 DB가 다른 세 DB와 다른 이유

개인일정/업무/학습은 각각 *진행 중이거나 아직 안 한* 항목을 담습니다. 완료작업은 이 항목들이 끝났을 때 옮겨가는 아카이브입니다: 단순히 제목만 기록하는 게 아니라 relation 속성으로 원본 페이지와 연결하고, 완료까지 걸린 시간과 완료일을 기록하며, 선택적으로 회고 메모도 담습니다. 그래서 완료 항목을 등록하는 작업은 두 단계로 이루어집니다: (1) 원본 항목을 찾아서 연결하고 그 항목도 완료 상태로 표시하는 것, (2) 여기 아카이브 레코드를 생성하는 것. (1)번을 건너뛰면 사용자가 완료했다고 생각하는데도 원본 페이지는 계속 미완료 상태로 남게 됩니다.

  - 업무: `collection://af79721d-da7c-400c-8475-f608a765da25` (relation 속성: `업무 연결`)

| 자료위치 | text | 일반 문자열 — 관련 파일/노트가 있는 위치(폴더, 문서 링크 등). 언급된 경우에만 |
| 회고 | text | 일반 문자열 — 진행 과정에 대한 짧은 회고. 사용자가 준 경우에만 |
| 개인일정 연결 / 업무 연결 / 학습 연결 | relation | **원본유형과 일치하는 것 하나만** 원본 페이지의 URL/ID로 설정하세요. 아래 "원본과 연결하기" 참고 |

### 완료일 설정

`notion-create-pages`는 단일 `완료일` 키가 아니라 확장된 컬럼명을 사용합니다:

- `"date:완료일:start"`: ISO-8601 날짜 또는 날짜시간 문자열. 사용자가 언제 끝났는지 지정하지 않으면 오늘로 기본 설정하세요.
- `"date:완료일:is_datetime"`: 특정 시간이 주어졌다면 `1`, 아니면 `0` 또는 생략
- `"date:완료일:end"`: 기간이 있는 값일 때만 사용하며, 보통은 생략합니다

### 원본과 연결하기

1. 어느 원본 데이터베이스(개인일정/업무/학습)에서 온 항목인지 파악하세요. 대개 사용자의 표현에서 명확합니다("치과 예약" → 개인일정, "랜딩페이지 개발" → 업무, "React 강의" → 학습). 정말 애매할 때만 물어보세요.
2. `notion-search`(또는 해당 데이터 소스에 대한 `notion-query-data-sources`)를 사용해 그 데이터베이스에 있는 실제 기존 페이지를 찾으세요. 사용자가 설명한 제목/내용으로 매칭합니다. 일치하는 페이지를 찾지 못하면 완료작업 항목은 그대로 생성하되 relation 연결은 건너뛰고, 원본을 찾지 못해 연결하지 못했다고 사용자에게 알리세요.
3. `notion-create-pages`에서 원본유형과 일치하는 relation 속성 하나를 설정하세요(예: `"업무 연결": ["<찾은 페이지 URL 또는 ID>"]`) — 이는 양방향 relation이라, 이쪽에서 연결하면 원본 페이지의 완료작업 필드에도 자동으로 반영됩니다.
4. 별도로, 원본 페이지 자체도 완료로 표시하세요: 개인일정 항목이면 `"완료여부": "__YES__"`로 설정하고, 업무나 학습 항목이면 상태 속성(`상태` 또는 `진행상태`)을 `"완료"`로 설정하세요. 이 작업은 원본 페이지에 `notion-update-page`로 수행합니다. 이 단계가 중요한 이유는 relation 연결만으로는 원본의 완료 상태 자체가 바뀌지 않기 때문입니다 — 이를 하지 않으면 "완료된 레코드와 연결되어 있지만 여전히 미완료로 표시됨"이라는 혼란스러운 상태가 됩니다.

## 등록 절차

1. "완료작업" 데이터베이스에 `notion-fetch`를 호출해 현재 데이터 소스 URL과 원본유형 옵션을 확인합니다.
2. 사용자 메시지에서 다음을 파악합니다: 제목, 원본유형(개인일정/업무/학습), 완료일(기본값 오늘), 담당자(기본값 본인), 언급된 소요시간/소요기간/자료위치/회고.
3. 위에서 설명한 대로 원본 페이지를 찾고, 그 완료 상태를 업데이트합니다.
4. `parent`를 `{"type": "data_source_id", "data_source_id": "<완료작업 데이터 소스 ID>"}`로 지정해 `notion-create-pages`를 호출하며, 원본 페이지를 찾았다면 일치하는 relation 속성도 포함합니다.
5. 생성된 페이지 URL을 사용자에게 알리고, 원본 항목의 상태가 업데이트되었는지 확인해준 뒤, 기록된 내용을 요약해줍니다.

## 완료 항목 조회 또는 수정

"최근에 완료한 거 뭐 있어?", "그 완료작업 회고 좀 추가해줘" 같은 요청의 경우:
- 완료작업 데이터 소스에 대해 `notion-search` 또는 `notion-query-data-sources`(SQL 모드, 예: `date:완료일:start` 기준 필터/정렬)를 사용해 항목을 찾으세요.
- 회고, 소요시간, 소요기간, 자료위치 수정은 찾은 특정 페이지에 `notion-update-page`를 사용하세요.

## 예시

**입력**: "React 기초 강의 다 들었어, 완료작업에 등록해줘. 3일 걸렸고 총 6시간 정도 썼어"

**처리**:
- 제목: "React 기초 강의 수강 완료"
- 원본유형: "학습" (강의 → 학습)
- 학습 DB에서 일치하는 페이지(예: "React 기초 강의")를 검색으로 찾음
- 해당 학습 페이지 업데이트: `"진행상태": "완료"`
- 완료일: 오늘
- 소요기간: 3, 소요시간: 6
- 담당자: 현재 사용자로 기본 설정(이를 알림)
- 학습 연결: 찾은 원본 페이지로 설정

**출력**: 생성된 완료작업 페이지 URL과 함께 "React 기초 강의를 완료작업에 기록하고, 학습 DB의 원본 항목도 '완료' 상태로 업데이트했습니다. 소요기간 3일, 소요시간 6시간." 같은 확인 메시지
