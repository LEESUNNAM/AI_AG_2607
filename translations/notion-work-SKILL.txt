# 노션 업무 등록

사용자가 언급한 업무 항목(작업, 프로젝트 산출물, 보고서 제출 등)을 노션의 "업무" 데이터베이스에 새 페이지로 등록합니다. Notion API 도구(`notion-fetch`, `notion-create-pages`, `notion-get-users`, `notion-search`)만 사용하며, 브라우저 자동화나 Playwright는 절대 사용하지 않습니다.

## 알려진 위치 정보

- 상위 페이지: "노션 db 연동 실습" (`https://app.notion.com/p/3cac1740333f80a1a657f705112bb28e`)
- 데이터베이스: "업무" (`https://app.notion.com/p/c6a2b4d7222248a3a5d550389d36bb25`)
- 데이터 소스(스키마 조회/쿼리용): `collection://af79721d-da7c-400c-8475-f608a765da25`

이 값들은 참고용 기본값이며 보장되는 값이 아닙니다. **매번 등록하기 전에 위 데이터베이스 URL로 `notion-fetch`를 호출해 최신 스키마를 확인하세요** — 상태/우선순위/프로젝트 옵션 목록이 바뀌었을 수 있고, 워크스페이스가 다르면 ID가 완전히 다릅니다. 알려진 ID로 `notion-fetch`가 실패하면 `notion-search`로 "업무"를 검색해 현재 URL을 다시 찾으세요.

## 속성 스키마 (2026-08-31 기준)

| 속성 | 타입 | 설정 방법 |
|---|---|---|
| 제목 | title | 문자열. 페이지 제목이며 필수입니다. |
| 상태 | status | `"시작 전"`, `"진행 중"`, `"완료"` 중 하나. 생략 시 기본값은 `"시작 전"`입니다 |
| 담당자 | person | 사용자 ID 문자열 배열. 아래 "담당자 설정" 참고 |
| 우선순위 | select | `"높음"`, `"중간"`, `"낮음"` 중 하나 |
| 프로젝트 | multi_select | `"개발"`, `"기획"`, `"마케팅"`, `"기타"` 중 0개 이상을 문자열 배열로 |
| 등록일 | date | 아래 "날짜 설정" 참고 |
| 마감일 | date | 아래 "날짜 설정" 참고 |
| 제출처 | text | 일반 문자열 — 산출물을 누구에게/어디로 제출하는지 (사람, 팀, 플랫폼 등) |
| 완료작업 | relation | 완료작업 데이터베이스와 연결하는 용도. 신규 업무 등록 시에는 사용하지 않습니다 |
| 잔여기한 | formula | **읽기 전용** — 마감일을 기준으로 자동 계산됩니다. 절대 직접 설정하려 하지 마세요 |

### 날짜 설정

**두 개의 별도 날짜 속성**이 있다는 점에 유의하세요 — 혼동하지 마세요:

- `등록일` = 업무가 등록/생성된 날짜. 사용자가 별도로 지정하지 않으면 오늘 날짜로 기본 설정해 등록일이 기록되도록 하세요.
- `마감일` = 마감 기한. 사용자가 실제로 마감일을 언급했을 때만 설정하고, 임의로 만들어내지 마세요.

각각에 대해 `notion-create-pages`는 단일 날짜 키가 아니라 확장된 컬럼명을 사용합니다:

- `"date:등록일:start"` / `"date:마감일:start"`: ISO-8601 날짜 또는 날짜시간 문자열 (예: `"2026-09-05"` 또는 `"2026-09-05T18:00:00"`)
- `"date:등록일:is_datetime"` / `"date:마감일:is_datetime"`: 특정 시간이 주어졌다면 `1`, 날짜만 있다면 `0` 또는 생략
- `"date:등록일:end"` / `"date:마감일:end"`: 기간이 있는/여러 날에 걸친 값일 때만 설정하고, 단일 날짜라면 생략하세요

사용자가 "다음주 금요일", "2주 후"처럼 상대적인 날짜를 말하면, 이 형식으로 변환하기 전에 오늘 날짜를 기준으로 절대 날짜로 환산하세요.

### 담당자 설정

사용자가 담당자를 지정하면 `notion-get-users`로 이름을 검색해 사용자 ID를 확인한 뒤, 그 ID를 문자열 배열로 `"담당자"`에 전달하세요. 사용자가 담당자를 지정하지 않으면 빈 값으로 두지 말고 현재 사용자(`notion-get-users`를 `user_id: "self"`로 호출)로 기본 설정하세요 — 담당자가 없는 업무는 놓치기 쉽기 때문입니다. 다만 이렇게 기본값을 적용했다는 사실을 사용자에게 알려, 실제로는 다른 사람의 업무라면 정정할 수 있게 하세요. 특정 이름이 워크스페이스 사용자와 매칭되지 않으면 그 이름은 제외하고 어떤 이름이 매칭되지 않았는지 알려주세요.

### 우선순위와 프로젝트 태그 추론

사용자가 우선순위나 프로젝트 카테고리를 명시적으로 말하면 그대로 사용하세요. 그렇지 않다면:
- `우선순위`는 추측하지 말고 설정하지 않은 채로 두세요 — 우선순위는 판단이 필요한 값이라 임의로 만들어내면 안 됩니다.
- `프로젝트`는 업무 내용상 명확할 때만 태그를 추론하세요(예: "새 랜딩페이지 개발"은 명백히 `"개발"`에 해당). 애매하면 억지로 `"기타"`로 채우지 말고 설정하지 않은 채로 두세요.

## 등록 절차

1. "업무" 데이터베이스에 `notion-fetch`를 호출해 현재 데이터 소스 URL과 상태/우선순위/프로젝트 옵션 목록을 확인합니다.
2. 사용자 메시지에서 다음을 추출합니다: 제목(필수), 마감일(있다면), 담당자(지정했다면, 아니면 본인으로 기본 설정), 우선순위(명시했다면), 프로젝트 태그(내용상 명확하다면), 제출처(언급했다면).
3. `parent`를 `{"type": "data_source_id", "data_source_id": "<위에서 확인한 데이터 소스 ID>"}`로 지정해 `notion-create-pages`를 호출합니다. 사용자가 다른 등록일을 지정하지 않았다면 `등록일`을 오늘로 설정하세요.
4. 생성된 페이지 URL을 사용자에게 알리고, 설정된 내용(제목/상태/마감일/담당자/우선순위/프로젝트)을 간단히 요약해줍니다.
5. 사용자가 이후에 업무의 상태, 마감일, 우선순위, 담당자 수정을 요청하면 `notion-search` 또는 `notion-query-data-sources`로 해당 항목을 찾은 뒤 `notion-update-page`로 반영하세요.

## 예시

**입력**: "새 랜딩페이지 개발 업무 등록해줘, 마감일은 다음주 금요일, 우선순위 높음으로"

**처리**:
- 제목: "새 랜딩페이지 개발"
- 상태: 설정하지 않음(기본값 "시작 전")
- 등록일: 오늘
- 마감일: "다음주 금요일"을 절대 날짜로 환산. `date:마감일:start` = 해당 날짜, `date:마감일:is_datetime` = 0
- 우선순위: "높음"
- 프로젝트: "개발" (제목의 "개발"에서 추론)
- 담당자: 현재 사용자로 기본 설정(이 사실을 알림)

**출력**: 생성된 노션 페이지 URL과 함께 "새 랜딩페이지 개발을 업무 DB에 등록했습니다 — 마감일 9월 X일(금), 우선순위 높음, 담당자는 본인으로 지정했습니다." 같은 확인 메시지
