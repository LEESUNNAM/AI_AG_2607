# 네이버 블로그 작성 (Naver Blog Writer)

주제 하나를 실제로 발행된 네이버 블로그 글로 만드는, 처음부터 끝까지의 과정입니다: 로그인 인계 → 주제 확인 → 템플릿 → 조사 → 초안 작성 → 임시저장 → 승인 → 발행. 순서가 중요합니다 — 사용자가 실제 초안을 직접 보고 승인하기 전까지는 아무것도 공개되지 않으며, 모든 브라우저 동작은 화면 밖이 아니라 사용자가 지켜볼 수 있는 화면에서 이루어집니다.

## 왜 이런 구조인가

실제 공개 블로그에 발행하는 것은 되돌리기 어려운 일방통행입니다 — 한 번 공개되면 누군가 읽고, 검색에 노출되고, 공유될 수 있으며, 실수를 알아차리기도 전에 그런 일이 벌어질 수 있습니다. 그래서 이 스킬은 조사 후 곧바로 발행하는 대신 항상 초안 단계에서 멈추고 확인을 받습니다. 또한 Claude는 사용자의 네이버 비밀번호에 절대 손대지 않습니다 — 로그인은 우회해야 할 빈틈이 아니라 의도적으로 사용자에게 넘기는 지점입니다. 그리고 사용자가 이 요청을 한 핵심 이유가 "진행 과정을 직접 지켜보는 것"이므로, 모든 과정은 헤드리스나 백그라운드 세션이 아니라 Playwright MCP의 눈에 보이는 브라우저 창을 통해 이루어집니다 — 이 세 가지 모두 단순한 예의가 아니라 이 스킬의 핵심 전제로 취급하세요.

## 1. 브라우저 도구 로드

Playwright MCP 도구가 아직 로드되지 않았다면 `ToolSearch`로 `select:mcp__playwright__browser_navigate,mcp__playwright__browser_snapshot,mcp__playwright__browser_click,mcp__playwright__browser_type,mcp__playwright__browser_take_screenshot,mcp__playwright__browser_find`를 불러오고 필요에 따라 추가합니다. Playwright MCP는 기본적으로 실제로 보이는 브라우저 창을 엽니다 — 사용자가 진행 상황을 지켜보는 것이 이 도구를 쓰는 이유이므로, 창을 숨기는 헤드리스 옵션 등을 추가하지 마세요.

## 2. 네이버 블로그 접속 — 로그인은 사용자에게 인계

`https://blog.naver.com`으로 이동합니다(로그인이 필요하다는 것을 이미 알고 있다면 `https://nid.naver.com/nidlogin.login`으로 바로 이동해도 됩니다). 스냅샷을 찍어 이미 로그인되어 있는지 확인합니다 — 헤더에 프로필 아이콘이나 "내 블로그" 링크가 보이면 로그인된 것이므로 바로 3단계로 넘어갑니다. 로그인되어 있지 않다면:

1. 네이버 로그인 화면에 도달하거나 클릭해서 이동합니다.
2. **여기서 멈추고 사용자에게 로그인 페이지가 열렸다고 알린 뒤 직접 로그인해달라고 요청합니다.** 아이디나 비밀번호(그리고 2단계 인증 절차)를 입력하는 것은, 사용자가 대신 입력해 달라고 제안하더라도 Claude가 절대 해서는 안 되는 일입니다 — 사용자가 직접 네이버 로그인 폼에 자신의 정보를 입력합니다.
3. 사용자가 완료했다고 말할 때까지 기다린 뒤, 다시 스냅샷을 찍어 로그인이 성공했는지(위와 동일한 헤더 단서로) 확인하고 나서 다음으로 넘어갑니다. 애매하다면 임의로 판단하지 말고 물어봅니다.

## 3. 글 주제 확인

로그인이 완료되면, 사용자가 원래 요청에서 이미 주제를 알려주지 않았다면 어떤 주제로 글을 쓸지 물어봅니다. 주제가 너무 넓어서(예: 그냥 "여행") 실질적인 내용을 쓰기 어렵다면 좁혀달라고 요청합니다 — 이 프로젝트의 다른 조사 기반 글쓰기와 같은 이유로, 범위가 정해지지 않은 주제는 얕은 글이 됩니다.

## 4. 템플릿 검색 및 추천

에디터("글쓰기" 버튼, 보통 사용자 본인 블로그 홈이나 헤더에서 접근)를 엽니다. 에디터 사이드바의 **템플릿** 패널을 엽니다 — 이야기, 정보·노하우, 리뷰, 맛집, 여행 등 카테고리별로 정리된 네이버의 내장 글 레이아웃 라이브러리입니다. 주제에 맞는 카테고리를 살펴보고, 실제로 그 주제에 어울리는 구조를 가진 템플릿을 2~3개 골라냅니다(제품 후기 글이라면 리뷰 템플릿, 방법 안내 글이라면 정보·노하우 템플릿처럼) — 목록의 첫 번째 템플릿을 그냥 고르지 않습니다.

선정한 템플릿들을 사용자에게 설명하고(이름/카테고리와 레이아웃이 강조하는 부분) 하나를 승인하거나, 템플릿 없이 쓰고 싶다고 말할 수 있도록 확인을 요청합니다. 사용자가 승인하지 않은 템플릿을 적용하지 마세요 — 이후에 쓸 글 전체 구조가 달라지기 때문입니다.

## 5. 조사 및 본문 작성

주제 자체에 대한 조사는 기본적으로 `WebSearch`/`WebFetch`를 사용합니다 — 더 빠르고, 검색 결과 페이지를 스크린샷으로 낭비하지 않습니다. 스니펫만으로 쓰지 말고 유망한 결과에서 실제 내용을 가져옵니다. 각 섹션에서 실제로 할 말이 있을 만큼 충분한 독립 출처를 확보하세요. 만약 주제가 조사보다는 개인적/경험적 성격이라면(예: 여행 일기) 근거 없는 사실을 지어내는 대신 사용자가 알려준 내용을 활용합니다.

오늘날 네이버 블로그가 실제로 읽히는 방식에 맞춰 쓰고, 정식 보고서처럼 쓰지 않습니다:

- **제목**: 구체적이고 명확하게, 가능하면 사람들이 검색할 만한 키워드를 앞쪽에 배치합니다 — 네이버 자체 검색·추천 노출에서는 애매하게 멋 부린 제목보다 무엇에 대한 글인지 명확히 밝힌 제목이 유리합니다.
- **도입부**: 1~2문장으로 즉시 눈길을 끄는 문장 — 네이버 모바일 피드는 첫 한두 줄만 미리보기로 보여주므로, 요점을 세 문장 뒤에 숨기지 않습니다.
- **본문**: 짧은 문단(2~4문장)으로 나누고, 요점이 하나 이상이면 소제목이나 번호 섹션으로 구분하며, 주제의 핵심 단어를 자연스럽게(억지로 채우지 않고) 본문 전체에 반복합니다 — 모바일에서 훑어보기 쉽고, 네이버 랭킹이 주제를 명확하고 일관되게 다루는 글을 우대하는 방식과도 맞습니다. 보통 사진이 들어가는 종류의 글이라면, 직접 이미지를 업로드할 수는 없으니(사용자가 파일을 제공하지 않는 한) 본문에 사진이 들어갈 자리를 표시해 둡니다(예: "[사진: ...]").
- **어조**: 대화체, 1인칭(-습니다/-해요체)으로, 업무 메모가 아니라 블로그답게 씁니다.
- **마무리**: 짧은 요약과, 템플릿/카테고리 관례상 필요하다면(리뷰·맛집 글 등에서 흔함) 관련 해시태그 한 줄을 덧붙입니다.

선택한 템플릿에 자체 섹션 틀이 있다면, 그 구조를 무시하지 말고 그 틀 안에 내용을 채워 넣습니다.

## 6. 글 입력 및 임시저장 — 절대 건너뛰지 않음

제목 입력란을 클릭해 제목을 입력하고, 이어서 본문을 입력합니다(문단 사이에 빈 줄을 두는 방식의 단일 `type` 동작으로 충분합니다). **저장**(임시저장 — 티스토리의 임시저장에 해당)을 클릭합니다. 사용자의 원래 요청이 곧바로 발행해달라는 것이었더라도 아직 **발행**을 클릭하지 않습니다 — 사용자가 실제 글 내용을 아직 보지 못했으므로, 표현 방식과 무관하게 초안 확인 후 승인 절차는 항상 적용됩니다.

## 7. 승인 요청 후 발행

초안이 저장되었음을 알리고, 공개되기 전에 확인해 달라고 요청합니다. 네이버 블로그의 발행 다이얼로그는 단순 공개/비공개보다 더 세분화된 공개 범위(전체공개, 이웃공개, 서로이웃공개, 비공개)를 제공하므로, 사용자가 아직 지정하지 않았다면 물어봅니다 — 누가 이 글을 읽을 수 있는지는 실제 영향이 있는 선택이므로 임의로 기본값을 정하지 않습니다. 승인과 공개 범위 선택을 모두 받았다면:

1. **발행**을 클릭해 발행 다이얼로그를 엽니다.
2. 해당하는 공개 설정 옵션을 선택하고, 사용자가 지정한 카테고리/태그가 있다면 설정합니다.
3. 다이얼로그의 최종 발행/확인 버튼을 클릭합니다.
4. 발행된 글로 이동해 정상적으로 열리는지 확인한 뒤, 결과와 실제 글 URL을 사용자에게 알립니다 — 이것으로 "저장된 글 페이지를 열어준다"는 요구사항도 함께 충족됩니다.

## 예외 상황

- **사용자가 조사 대신 직접 자료를 제공하는 경우**: 웹 조사를 건너뛰고 사용자가 준 내용으로 글을 구성하며, 분량을 채우기 위해 추가 주장을 지어내지 않습니다.
- **어울리는 템플릿이 없는 경우**: 그렇다고 말하고, 억지로 맞지 않는 템플릿을 적용하는 대신 템플릿 없이 작성하겠다고 제안합니다.
- **사용자가 "그냥 바로 발행해"라고 명시적으로 말하는 경우**(승인 단계 생략 요청): 그래도 먼저 임시저장을 하고 제목과 간단한 요약을 보여준 뒤 발행합니다 — 이 게이트의 목적은 절차적 번거로움이 아니라 공개된 글의 실수는 되돌리기 어렵다는 데 있으므로, 초안 단계를 생략해달라는 요청이 있어도 확인 절차 자체는 생략하지 않습니다.
- **작업 도중 로그인 세션이 만료되는 경우**: 이동 중 예상치 못하게 로그인 페이지로 돌아간다면, 무작정 재시도하지 말고 멈춘 뒤 다시 사용자에게 로그인을 인계합니다.
- **사용자가 이미 발행된 글의 수정이나 공개 범위 변경을 요청하는 경우**: 해당 글의 관리/수정 화면(내 블로그 → 글 관리, 또는 글 URL로 직접 접근)으로 이동해 변경한 뒤 동일한 방식으로 저장합니다 — 주제/템플릿/초안 작성 흐름 전체를 처음부터 다시 진행할 필요는 없습니다.
