# 리서치 보고서 (xlsx)

주제 하나만 주어졌을 때(리서치 모드) 또는 사용자가 지목한 기존 스프레드시트 파일이 있을 때(분석 모드), 서식이 갖춰지고 출처가 명확한 `.xlsx` 워크북을 만듭니다. 두 모드 모두 저장소 루트의 `scripts/create_xlsx.py`를 거치며, 이 스크립트가 이미 한글 폰트 렌더링, ID 열 삽입, 헤더/인용구/본문 서식, 성장률·비교 데이터에 대한 자동 차트 생성 문제를 해결해두었으므로 openpyxl 호출을 직접 손으로 작성하지 마세요.

## 왜 이런 형태인가

스프레드시트 결과물은 독자가 빠르게 훑어볼 수 있어야 하고(번호가 매겨진 ID 열, 굵은 헤더) 숫자를 신뢰할 수 있어야(진짜 출처, 올바른 비율로 스케일된 퍼센트, 한눈에 추세를 볼 수 있는 차트) 비로소 쓸모가 있습니다. `create_xlsx.py`의 `SheetBuilder.save()`와 `format_workbook()`은 이를 통해 작성된 모든 데이터에 이런 서식을 이미 자동으로 적용합니다 — 당신이 할 일은 서식을 다시 구현하는 것이 아니라 표에 좋은 데이터를 채워 넣는 것입니다.

## 0. 모드 결정하기

- **리서치 모드**: 사용자가 특정 파일 없이 주제만 제시하는 경우 ("2026 AI 에이전트 시장", "국내 OTT 서비스 요금제 비교"). §1로 이동하세요.
- **분석 모드**: 사용자가 이미 존재하는 특정 `.xlsx`나 `.csv` 파일을 언급하는 경우 (경로, "다운로드 폴더에 있는 파일", 첨부파일 등). §4로 이동하세요.

요청이 서술형(설명, 내러티브 보고서)에 더 적합해 보인다면 표 형태를 억지로 만들지 말고 `research-report-docx` 스킬을 대신 사용하세요 — 표 형태가 아닌 콘텐츠에 스프레드시트를 강제하지 마세요.

## 1. 주제 확정하기 (리서치 모드)

유추할 수 있거나 기본값으로 정할 수 있는 것들은 굳이 물어보지 마세요:
- **언어**: 사용자가 질문하는 언어에 맞추세요 (이 프로젝트는 기본적으로 한국어).
- **표 범위**: 사용자가 더 많거나 적게 요청하지 않는 한, 개요 표 1개 + 주요 하위 주제(연도별, 기업별, 지역별 등)별 비교 표 1개를 기본으로 합니다. 주제가 한 번에 표로 정리하기엔 너무 넓다면(예: 그냥 "AI"), 추측하지 말고 사용자에게 범위를 좁혀달라고 요청하세요.
- **참고자료 시트**: 항상 포함하세요 — 추적 가능한 근거 없는 표는 신뢰할 수 없습니다.

## 2. WebSearch/WebFetch로 조사하기

일반적인 리서치 작업과 동일한 원칙을 따르세요: `WebSearch`로 출처를 찾은 다음, 유망한 결과에 `WebFetch`를 사용해 스니펫만으로 작성하지 말고 실제 내용을 가져오세요. 이번 결과물은 숫자 표이므로 특히 다음에 주의하세요:

- **실제 수치를 확보**하세요, 단순 주장이 아니라 — 숫자 열에 애매한 텍스트가 들어간 비교 표는 쓸모가 없습니다.
- **단위와 스케일**: 수치가 억/조 원인지, %인지, 전년 대비인지 전분기 대비인지 등을 확인하세요 — 이는 사용할 `number_format`을 결정합니다 (§3 참고).
- 시간에 민감한 내용은 게시일을 기록하고, 출처마다 수치가 다르면 하나를 조용히 고르지 말고 둘 다 표에 남기고 그 사실을 표시하세요.
- 진행하면서 `(출처 제목, url)` 목록을 계속 기록해두세요 — 참고자료 시트에 그대로 필요합니다.

## 3. 워크북 만들기 (리서치 모드)

```python
import sys
sys.path.insert(0, "scripts")
from create_xlsx import SheetBuilder

wb = SheetBuilder(title="AI 에이전트 시장 조사", main_color="1F4E79")
wb.add_title("연도별 시장 규모")
wb.write_table(
    headers=["연도", "시장 규모(억 달러)", "전년 대비 성장률"],
    rows=[
        [2023, 51, 0.28],
        [2024, 78, 0.53],
        [2025, 121, 0.55],
    ],
)

wb.add_sheet("기업별 비교")
wb.add_title("주요 기업 비교")
wb.write_table(
    headers=["기업", "주요 제품", "2025 매출(억 달러)"],
    rows=[
        ["OpenAI", "ChatGPT / Agents SDK", 37],
        ["Anthropic", "Claude / Agent SDK", 20],
    ],
)

wb.add_sheet("참고자료")
wb.add_title("참고자료")
wb.write_table(
    headers=["제목", "URL"],
    rows=[
        ["OpenAI 2025 revenue report", "https://..."],
        ["Anthropic funding announcement", "https://..."],
    ],
)

wb.save("research/AI_에이전트_시장_조사.xlsx")
```

참고 사항:
- `wb.save()`는 전체 자동 서식 처리를 대신 수행합니다: 모든 표에 `ID` 열, 굵은 헤더, 정규화된 10pt 본문 폰트를 적용하고 — 리서치 데이터에서 특히 중요한 부분으로 — 각 시트의 헤더에서 성장률/비율 관련 키워드(성장률, 증가율, 전년 대비, 점유율 등)나 연도/월/분기 형태의 범주 열을 자동으로 탐지해 **꺾은선 또는 막대 차트를 자동으로 추가**합니다. 따라서 표에 시각화할 만한 추세가 있다면 열 이름을 인식 가능하게만 지어주면(예: "YoY"가 아니라 "전년 대비 성장률") 추가 코드 없이 차트가 나타납니다.
- 소수 형태의 성장률 값(`0.28`)은 자동으로 `28.0%`로 서식이 적용됩니다. 원본 수치가 이미 스케일된 상태(예: `28`이 28%를 의미)라면 그대로 두세요 — 자동 서식 처리기가 스케일을 감지해 이중 변환하지 않습니다.
- 주제별로 시트를 나누면 표를 읽기 쉽게 유지할 수 있습니다. `add_sheet`를 피하려고 관련 없는 비교 내용을 한 시트에 억지로 몰아넣지 마세요.
- 항상 참고자료 시트(제목, URL 열)로 마무리하세요 — 위에 나온 모든 숫자의 근거 자료입니다.

## 4. 파일 읽고 이해하기 (분석 모드)

무엇을 만들지 결정하기 전에 사용자가 지목한 파일을 먼저 찾아 열어보세요:

```python
from openpyxl import load_workbook

wb_in = load_workbook("다운로드/판매실적.xlsx")
for ws in wb_in.worksheets:
    print(ws.title, ws.dimensions)
```

`.csv`의 경우 표준 라이브러리 `csv` 모듈로 헤더와 행을 읽으세요.

그다음 적절한 방식을 선택하세요:

- **파일이 단순히 정리/서식 적용만 필요한 경우** ("정리해줘", "표 예쁘게 만들어줘", "차트 추가해줘") 이고 기존 구조가 이미 합리적(헤더 행 1개 + 표 형태 데이터)이라면: `load_and_format`을 바로 사용하세요 — 정확히 이 용도로 만들어졌고, 파일 없음/입출력 경로 동일/저장 실패 같은 오류 상황도 이미 처리되어 있습니다.

  ```python
  import sys
  sys.path.insert(0, "scripts")
  from create_xlsx import load_and_format

  load_and_format("다운로드/판매실적.xlsx", "research/판매실적_분석.xlsx")
  ```

- **파일에 실제 분석이 먼저 필요한 경우**(합계, 평균, 파생 비교, 여러 시트/파일 결합 등) — 순수 Python으로 수치를 계산한 다음, 평소처럼 워크북에 기록하고 원본 데이터를 함께 옮겨 담을 때도 `format_workbook`이 전체를 서식 처리하도록 하세요:

  ```python
  import sys
  sys.path.insert(0, "scripts")
  from create_xlsx import SheetBuilder, format_workbook
  from openpyxl import load_workbook

  wb_in = load_workbook("다운로드/판매실적.xlsx")
  src = wb_in.active
  # ... src의 행에서 순수 Python으로 요약 계산 ...

  wb = SheetBuilder(title="판매실적 분석")
  wb.write_table(headers=["부서", "총 매출", "평균 매출"], rows=summary_rows)
  wb.save("research/판매실적_분석.xlsx")
  ```

  `SheetBuilder`로 새로 만드는 대신 직접 조립한 `Workbook` 객체(예: 불러온 파일을 복사해 요약 시트를 추가하는 경우)가 있다면 `format_workbook(some_workbook)`도 바로 임포트해서 쓸 수 있습니다 — `.save()` 전에 한 번 호출하면 모든 시트에 동일한 ID/헤더/인용구/본문/차트 처리가 적용됩니다.

- CSV 입력의 경우, 행을 읽어 바로 `SheetBuilder.write_table`에 넘기는 것이 가장 간단합니다 — 그러면 일반 CSV에 대해서도 서식/차트 파이프라인 전체를 새로 구현할 필요 없이 그대로 얻을 수 있습니다.

## 5. 저장하고 결과 보고하기

리서치 모드와 분석 모드 결과물 모두 `.docx` 보고서에 이미 쓰이는 프로젝트 관례와 동일하게 `research/` 폴더에 저장하세요 (`research/<주제>_조사_보고서.xlsx`, `research/<원본파일명>_분석.xlsx`). 필요하면 폴더를 새로 만드세요 — `SheetBuilder.save()`와 `load_and_format()`이 이미 상위 디렉터리를 생성합니다.

저장 후 채팅에서 사용자에게 알려주세요: 파일 경로, 포함된 시트 목록, 데이터가 보여주는 내용에 대한 1~2문장 요약, 차트가 생성되었는지 여부, 사용한 출처 개수(리서치 모드) 또는 변경된 내용(분석 모드). 표 내용을 채팅에 그대로 붙여넣지 마세요 — `.xlsx` 파일 자체가 결과물입니다.

## 예외 상황

- **주제에 대한 신뢰할 만한 수치 데이터가 거의 없는 경우**: 참고자료 시트와 채팅 요약 모두에 그 사실을 밝히세요 — 그럴듯해 보이는 숫자를 지어내는 것은 표가 없는 것보다 나쁩니다.
- **출처마다 수치가 다른 경우**: 하나를 조용히 고르지 말고 표에 둘 다 남기세요(예: 행 2개, 또는 비고 열).
- **참조한 파일이 존재하지 않는 경우**: `load_and_format`이 이미 이를 명확히 알려줍니다. 파일을 직접 먼저 읽는다면 여는 것보다 먼저 `Path.exists()`를 확인하고 트레이스백이 노출되게 두지 말고 사용자에게 알리세요.
- **파일에 시트가 여러 개이거나 헤더 행이 명확하지 않은 경우**: 각 시트를 독립적으로 처리하세요. `format_workbook`은 헤더 행을 찾을 수 없는 시트는 이미 건너뛰므로 파일 전체가 실패하지 않습니다.
- **모드가 모호한 경우**(사용자가 주제와 파일을 동시에 제시, 예: "이 파일 참고해서 이 주제로 조사해줘"): 파일을 웹 조사와 함께 1차 출처로 취급하고, 참고자료 시트에 그렇게 명시하세요.
- **사용자가 한국어가 아닌 워크북을 원하는 경우**: 구조는 동일하게 유지하되 셀 값뿐 아니라 헤더/시트 이름도 함께 번역하세요.
