# 노션 개인일정 등록

사용자가 언급한 개인 일정(약속, 가족 모임, 병원 예약 등)을 노션의 "개인일정" 데이터베이스에 새 페이지로 등록합니다. Notion API 도구(`notion-fetch`, `notion-create-pages`, `notion-get-users`, `notion-search`)만 사용하며, 브라우저 자동화나 Playwright는 절대 사용하지 않습니다.

## 알려진 위치 정보

- 상위 페이지: "노션 db 연동 실습" (`https://app.notion.com/p/3cac1740333f80a1a657f705112bb28e`)
- 데이터베이스: "개인일정" (`https://app.notion.com/p/efe330c63ad94be989e6c33d4c1c663e`)
- 데이터 소스(스키마 조회/쿼리용): `collection://191e7deb-2d91-45c3-88e3-3e5c3afe7dc7`

이 값들은 참고용 기본값이며 보장되는 값이 아닙니다. **매번 등록하기 전에 위 데이터베이스 URL로 `notion-fetch`를 호출해 최신 스키마를 확인하세요.** 이 스킬이 작성된 이후 선택 옵션이 추가되거나 이름이 바뀌었을 수 있고, 워크스페이스가 다르면 ID 자체가 완전히 다릅니다. 알려진 ID로 `notion-fetch`가 실패하면 `notion-search`로 "개인일정"을 검색해 현재 URL을 다시 찾으세요.

## 속성 스키마 (2026-08-31 기준)

| 속성 | 타입 | 설정 방법 |
|---|---|---|
| 제목 | title | 문자열. 페이지 제목이며 필수입니다. |
| 날짜 | date | 아래 "날짜 설정" 참고 |
| 카테고리 | select | `"가족"`, `"건강"`, `"약속"`, `"기타"` 중 하나 |
| 완료여부 | checkbox | `"__YES__"`(완료) 또는 `"__NO__"`(미완료). 생략 시 기본값은 미완료입니다 |
| 함께하는 사람 | person | 사용자 ID 문자열 배열. 아래 "참석자 설정" 참고 |
| 장소 | place | **API로 직접 설정 불가**(좌표 기반 특수 타입). 아래 "장소 처리" 참고 |
| 완료작업 | relation | 완료작업 데이터베이스와 연결하는 용도. 신규 일정 등록 시에는 사용하지 않습니다 |

### 날짜 설정

`notion-create-pages`는 날짜 속성에 단일 `날짜` 키를 받지 않고, 확장된 컬럼명을 사용합니다:

- `"date:날짜:start"`: ISO-8601 날짜 또는 날짜시간 문자열 (예: `"2026-09-05"` 또는 `"2026-09-05T18:00:00"`)
- `"date:날짜:is_datetime"`: 특정 시간이 주어졌다면 `1`, 날짜만 있는 종일 이벤트라면 `0` 또는 생략
- `"date:날짜:end"`: 여러 날에 걸친/기간이 있는 이벤트일 때만 설정합니다. 단일 날짜라면 아예 넣지 마세요

사용자가 "다음주 화요일 3시"처럼 상대적인 날짜/시간을 말하면, 이 형식으로 변환하기 전에 오늘 날짜를 기준으로 절대 날짜로 환산하세요.

### 참석자 설정

사용자가 함께하는 사람을 언급하면("OO랑 같이") `notion-get-users`로 이름을 검색해 사용자 ID를 확인한 뒤, 그 ID들을 문자열 배열로 `"함께하는 사람"`에 전달하세요. 특정 이름이 워크스페이스 사용자와 매칭되지 않으면 그 이름은 속성에서 조용히 제외하고, 어떤 이름이 왜 매칭되지 않았는지 사용자에게 알려주세요.

### 장소 처리

`장소` 속성은 노션의 "place" 타입으로, 일반 텍스트 문자열을 거부하는 경우가 많습니다:

1. 먼저 `"장소"` 키에 위치를 일반 문자열로 넣어 시도해보세요.
2. API가 이를 거부하면 해당 속성 설정은 건너뛰고, 대신 페이지 `content`에 "장소: OO" 같은 한 줄을 추가해 정보가 유실되지 않게 하세요.
3. 두 방식 중 어느 쪽으로 위치 정보가 저장되었는지 사용자에게 간단히 알려주세요.

## 등록 절차

1. "개인일정" 데이터베이스에 `notion-fetch`를 호출해 현재 데이터 소스 URL과 카테고리 옵션을 확인합니다.
2. 사용자 메시지에서 다음을 추출합니다: 제목(필수), 날짜/시간(필수 — 없으면 물어보세요), 카테고리(가족/건강/약속/기타 중 가장 가까운 것으로 추론하고, 정말 애매하면 기타로 기본 설정한 뒤 사용자에게 알립니다), 참석자(있다면), 장소(있다면).
3. `parent`를 `{"type": "data_source_id", "data_source_id": "<위에서 확인한 데이터 소스 ID>"}`로 지정해 `notion-create-pages`를 호출합니다.
4. 생성된 페이지 URL을 사용자에게 알리고, 설정된 내용(제목/날짜/카테고리/참석자 등)을 간단히 요약해줍니다.
5. 사용자가 이후에 기존 항목의 날짜, 카테고리, 완료 상태 수정을 요청하면 `notion-search` 또는 `notion-query-data-sources`로 해당 항목을 찾은 뒤 `notion-update-page`로 반영하세요.

## 예시

**입력**: "다음주 화요일 저녁 7시에 치과 예약 있어, 노션에 등록해줘"

**처리**:
- 제목: "치과 예약"
- 날짜: "다음주 화요일"을 절대 날짜로 환산. `date:날짜:start` = 해당 날짜의 `T19:00:00`, `date:날짜:is_datetime` = 1
- 카테고리: "건강"
- 완료여부: 설정하지 않음(기본값 미완료)

**출력**: 생성된 노션 페이지 URL과 함께 "치과 예약을 9월 X일(화) 오후 7시, 카테고리 '건강'으로 개인일정에 등록했습니다." 같은 확인 메시지
